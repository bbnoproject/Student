# HTML 페이지 기획

이 문서는 수정된 목적 기반 기획을 실제 HTML 페이지 구조로 옮기기 위한 화면 설계서다. 현재 앱은 정적 HTML 2개와 JavaScript 렌더링으로 구성되어 있으므로, 물리 파일과 해시 라우트를 함께 기준으로 삼는다.

## 1. 전체 페이지 구조

현재 물리 HTML 파일은 아래 2개를 유지한다.

- `App/index.html`: 전체 과정과 학생 목록, 피드백 기능을 담는 메인 앱 셸
- `App/student.html`: 학생 1명에 대한 상세 분석 앱 셸

`App/index.html` 내부 해시 라우트는 아래처럼 나눈다.

- `#overview`: 과정 개요
- `#process`: 학습과정 > 과정 개요
- `#process/m1` ~ `#process/m6`: 학습과정 > 마일스톤 상세
- `#students`: 학생관리
- `#feedback`: 피드백

공통 상단에는 다음 요소를 둔다.

- 서비스 타이틀
- 상단 메뉴: `개요`, `학습과정`, `학생관리`, `피드백`
- 학생 검색
- 다크/라이트 모드 아이콘

상단 영역은 sticky로 고정하고, 본문 스크롤과 독립적으로 유지한다.

## 2. 개요 페이지

URL: `App/index.html#overview`

목적:

- 과정 파악
- 학생 분류 진입
- 과정 보고서 진입
- 학생 멘토링 진입

사용자가 이 페이지에서 답해야 하는 질문:

- 현재 과정은 얼마나 진행되었는가?
- 이번 기수의 학생 구성은 어떤가?
- 운영자가 지금 가장 먼저 봐야 할 학생 유형은 무엇인가?
- 이 대시보드를 어떤 목적에 맞춰 사용하면 되는가?

섹션 구성:

1. 과정 진행 요약
   - 진행률
   - 현재 주차
   - 진행 세션 수
   - 전체/일반/과정이탈/평균 종합/제출률

2. 운영 목적별 활용 지도
   - 학생 분류
   - 학생 파악
   - 과정 파악
   - 과정 보고서
   - 학생 멘토링

3. 전체 학생 분포
   - 상태 분포 도넛
   - 운영 분류 막대

4. 이번 기수 기본 통계
   - 나이
   - 성별
   - 학력
   - 지역

5. 현재까지 파악된 학생 특징
   - 학습 흐름 복합 케이스
   - 반복 케이스 수
   - 예시 학생

필요한 상호작용:

- 목적 카드 클릭 시 관련 페이지로 이동
- 운영 분류/상태 분포에서 학생관리 필터로 연결
- 케이스 카드 클릭 시 학생관리 또는 케이스 상세로 연결하는 기능은 추후 추가

## 3. 학습과정 페이지

URL:

- `App/index.html#process`
- `App/index.html#process/m1` ~ `App/index.html#process/m6`

목적:

- 과정 보고서
- 과정 파악
- 학생 파악

페이지 내부 메뉴:

- 과정 개요
- M1 모집 ~ 개강
- M2 개강 ~ 1차 프로젝트 종료
- M3 1차 프로젝트 종료 ~ 2차 프로젝트 종료
- M4 2차 프로젝트 종료 ~ 3차 프로젝트 종료
- M5 3차 프로젝트 종료 ~ 4차 프로젝트 종료
- M6 4차 프로젝트 종료 ~ 종강

### 3.1 학습과정 > 과정 개요

사용자가 이 화면에서 답해야 하는 질문:

- 전체 과정은 시간상 어디까지 왔는가?
- 학생 평균 프로파일은 마일스톤별로 어떻게 변했는가?
- 현재 시점은 어떤 마일스톤인가?

섹션 구성:

1. 과정 요약 지표
   - 진행률
   - 현재 구간
   - 평균 프로파일
   - 프로젝트 기록 수
   - 위험 출결 수

2. 마일스톤 평균 프로파일 그래프
   - x축: M1~M6
   - y축: 평균 프로파일
   - 현재 시점 포인트 강조

3. 마일스톤 요약 카드
   - 마일스톤명
   - 기간
   - 평균 프로파일
   - 클릭 시 해당 마일스톤 상세로 이동

4. 전체 마일스톤 타임라인
   - 주요 특이사항
   - 관찰 영역
   - 상담/프로젝트/위험출결 건수

### 3.2 학습과정 > 마일스톤 상세

사용자가 이 화면에서 답해야 하는 질문:

- 이 구간에서 어떤 수업/프로젝트/운영 이벤트가 있었는가?
- 이 구간에서 학생들에게 어떤 변화나 위험 신호가 나타났는가?
- 운영자가 확인해야 할 학생은 누구인가?

섹션 구성:

1. 마일스톤 헤더
   - 마일스톤 번호
   - 기간
   - 현재 구간 여부
   - 이전/다음/과정 개요 이동

2. 상단 요약
   - 평균 프로파일
   - 성장 변화
   - 프로젝트 기록
   - 상담/출결

3. 구간 기록 구성
   - 프로젝트
   - 상담
   - 출결
   - 위험출결
   - 진로

4. 주요 특이사항
   - 복합 케이스
   - 건강 관리 관찰
   - 데일리체크인 리듬 흔들림
   - 회고 기반 성장

5. 관찰 영역
   - 자기조절
   - 참여 지속성
   - 협업
   - 회복탄력성
   - 성찰
   - 진로 목적성

6. 학생별 케이스 예시
   - 학생명
   - 케이스명
   - 요약
   - 근거

7. 확인할 학생
   - 케이스가 있는 학생
   - 평균 프로파일이 낮은 학생
   - 클릭 시 학생 상세로 이동

추후 보강:

- 마일스톤별 보고서 문장 자동 생성
- PDF/HTML 리포트 출력
- 특정 케이스 클릭 시 학생 상세의 해당 근거 위치로 이동

## 4. 학생관리 페이지

URL: `App/index.html#students`

목적:

- 학생 분류
- 학생 파악
- 멘토링 대상 탐색

사용자가 이 화면에서 답해야 하는 질문:

- 현재 학생들은 어떤 상태와 운영 분류로 나뉘는가?
- 특정 분류에 해당하는 학생은 누구인가?
- 어떤 수치 기준으로 학생을 정렬해 볼 수 있는가?

섹션 구성:

1. 상태 요약
   - 전체
   - 일반
   - 취업
   - 과정이탈

2. 운영 분류 카테고리
   - 종합우수
   - 성장우수
   - 집중지원
   - 협업강점
   - 진로준비
   - 참여관찰
   - 일반

3. 학생 표
   - 학생명
   - 상태
   - 운영 분류
   - 종합
   - 성장
   - 지원
   - 협업
   - 진로
   - 위험출결
   - 제출률

필요한 상호작용:

- 상태 카드 클릭 시 상태 필터
- 운영 분류 카드 클릭 시 분류 필터
- 표 헤더 클릭 시 정렬
- 학생명 클릭 시 학생 상세 이동
- 상단 검색과 연동

추후 보강:

- 유사 학생 비교
- 분류 변경 이력
- 운영자 수동 분류 보정

## 5. 피드백 페이지

URL: `App/index.html#feedback`

목적:

- 학생 멘토링
- 취업 지원
- 제출 문서 피드백

사용자가 이 화면에서 답해야 하는 질문:

- 어떤 학생에게 어떤 형태의 피드백을 생성할 것인가?
- 제출 문서와 저장된 학생 데이터를 어떻게 함께 AI에 전달할 것인가?
- Gemini 외 다른 모델을 사용할 수 있도록 중간 형식이 준비되어 있는가?

섹션 구성:

1. 피드백 설정
   - 학생 선택
   - 피드백 형태 선택
   - AI 제공자 선택
   - 모델명
   - API Key

2. 제출 자료 입력
   - 파일 업로드
   - 텍스트 붙여넣기

3. 학생 데이터 스냅샷
   - 운영 분류
   - 주요 케이스
   - 진로 준비도

4. 중간다리 JSON
   - `student-feedback-bridge/v1`
   - 학생 기본 정보
   - 평가 준거
   - 학생 분석 데이터
   - 제출 문서 정보

5. 생성 결과
   - 현재는 로컬 초안 생성
   - 추후 실제 AI API 결과 표시

추후 보강:

- Gemini API 실제 호출
- `.docx`, `.pdf` 본문 추출
- 자기소개서 외 이력서/포트폴리오/면접 답변 피드백 타입 추가
- 피드백 결과 저장 및 학생 상세 연결

## 6. 학생 상세 페이지

URL: `App/student.html?id=학생ID`

목적:

- 학생 파악
- 학생 멘토링
- 취업 지원

사용자가 이 화면에서 답해야 하는 질문:

- 이 학생은 어떤 사람인가?
- 과정 중 어떤 변화가 있었는가?
- 어떤 위험 신호와 회복 신호가 있었는가?
- 멘토링할 때 어떤 근거를 봐야 하는가?

섹션 구성:

1. 학생 기본 요약
   - 이름
   - 상태
   - 운영 분류
   - 기본 정보
   - 주요 강점/주의 영역

2. 현재 능력치와 성향 프로파일
   - 6개 평가 준거
   - 판단 이유
   - 루브릭 팝업

3. 자기표현과 발화 특징
   - 나이/성별/학력은 해석 맥락으로만 표시
   - 모집서류, 체크인, 회고, 진로 문서의 표현 방식 요약
   - 구체성, 주도성, 성찰, 관계 언어, 진로 언어, 정서/불확실 표현

4. 분류 사유
   - 각 운영 분류 기준별 해당/미해당
   - 판단 근거

5. 협업 변화
   - 프로젝트별 체크인
   - 회고
   - 역할 수행
   - 변화 라벨

6. 학습 흐름 복합 케이스
   - 건강 관리 관찰
   - 컨디션 관리 연쇄
   - 회고 기반 성장
   - 면담 후 회복
   - 진로 문서 개선

7. 마일스톤 성장 곡선
   - M1~M6 점수 변화
   - 이벤트 요약
   - 관찰 영역

8. 최근 주요 이벤트
   - 프로젝트
   - 출결
   - 상담
   - 진로

9. 정보 수정
   - 브라우저 localStorage 기반 임시 편집
   - 다른 PC로 자동 전달되지 않음

추후 보강:

- 멘토링 메모 저장
- 후속 조치 체크리스트
- 피드백 결과 연결
- 이상 신호 타임라인 강조

## 7. 우선 구현 순서

1. 개요 페이지 목적 보드와 과정 요약을 안정화한다.
2. 학습과정 마일스톤 상세를 보고서형 문장으로 보강한다.
3. 학생 상세에 위험 신호 타임라인과 추천 대응을 추가한다.
4. 피드백 페이지에 파일 파서와 Gemini API를 연결한다.
5. 학생관리에서 유사 학생 비교와 분류 변경 이력을 추가한다.

## 8. HTML/JS 구현 원칙

- HTML 파일은 앱 셸만 담당하고, 데이터 기반 본문은 JavaScript 렌더링으로 유지한다.
- 해시 URL은 공유 가능한 상태를 가져야 한다.
- 운영자가 보는 첫 화면에는 목적, 현황, 다음 행동이 함께 보여야 한다.
- 점수만 보여주지 말고 판단 근거와 시간 흐름을 함께 제공한다.
- 출결, 건강, 협업, 진로는 서로 다른 판단 축으로 분리한다.
- 피드백/멘토링 기능은 학생 데이터와 제출 문서를 분리하지 않고 함께 읽을 수 있어야 한다.
