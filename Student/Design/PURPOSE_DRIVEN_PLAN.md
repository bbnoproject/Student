# 목적 기반 개선 기획

이 문서는 학생 대시보드가 어떤 운영 목적을 달성해야 하는지와, 현재 구현 상태에서 어떤 내용을 우선 보강해야 하는지를 정리한다.

## 1. 학생 분류

목적: 학생의 특징을 분석하고 유사한 학생 기준으로 분류해, 과정 운영자가 학생 타입을 빠르게 파악한다.

현재 구현:

- `학생관리`에서 운영 분류 카테고리와 상태 분류를 확인한다.
- 학생 상세에서 각 분류 기준별 판단 사유를 확인한다.
- `종합우수`, `성장우수`, `집중지원`, `협업강점`, `진로준비`, `참여관찰`, `일반`을 사용한다.

필요한 보강:

- 같은 분류 안에서 유사 학생을 비교하는 뷰가 필요하다.
- 분류가 바뀐 학생은 언제, 어떤 데이터 때문에 바뀌었는지 추적해야 한다.
- 운영자가 분류 사유를 조정할 수 있는 피드백 루프가 필요하다.

## 2. 학생 파악

목적: 학생이 과정 시작부터 끝까지 어떤 변화를 보였는지 파악하고, 위험 신호를 조기에 캐치해 대응한다.

현재 구현:

- 학생 상세에서 마일스톤별 변화, 협업 변화, 학습 흐름 복합 케이스를 확인한다.
- 병가와 위험 출결을 분리해 본다.
- 데일리체크인, 회고, 상담, 출결, 진로 문서를 시간 순서로 조합한다.

필요한 보강:

- 이상 신호를 날짜 중심으로 더 명확하게 표시해야 한다.
- 위험 신호가 발생했을 때 추천 대응을 함께 보여줘야 한다.
- 상담/멘토링 이후 학생 상태가 회복되었는지 추적해야 한다.

## 3. 과정 파악

목적: 전체 학생 분포와 반복 케이스를 파악해 과정의 특징을 이해하고 운영 효율을 높인다.

현재 구현:

- `개요`에서 과정 진행률, 상태 분포, 운영 분류, 나이/성별/학력/지역 통계를 확인한다.
- 전체 학생의 반복 케이스를 요약한다.
- 목적별 운영 보드로 화면의 활용 목적을 안내한다.

필요한 보강:

- 이전 기수와 비교할 수 있는 기준이 필요하다.
- 특정 마일스톤에서 반복적으로 발생하는 운영 이슈를 자동 요약해야 한다.
- 개입 후 개선된 케이스와 개선되지 않은 케이스를 분리해야 한다.

## 4. 과정 보고서

목적: 과정 전체 흐름을 시간선에 맞춰 볼 수 있는 보고서로 사용한다.

현재 구현:

- `학습과정`에서 과정 개요와 `M1~M6` 마일스톤 상세를 본다.
- `#process/m5`처럼 특정 마일스톤으로 직접 진입할 수 있다.
- 현재 시점은 그래프 포인트 색상으로 강조한다.

필요한 보강:

- 보고서 출력용 문장 요약이 필요하다.
- PDF 또는 HTML 리포트로 내보내는 기능이 필요하다.
- 마일스톤별 주요 학생, 주요 사건, 운영 대응을 보고서 형식으로 묶어야 한다.

## 5. 학생 멘토링

목적: 학생 개인 정보를 바탕으로 멘토링과 취업 지원에 활용한다.

현재 구현:

- 학생 상세에서 개인별 정보, 변화, 케이스, 진로 준비도를 확인한다.
- `피드백` 메뉴에서 학생 데이터와 제출 문서를 AI 전달용 중간다리 JSON으로 묶는다.
- 자기소개서 피드백 준거를 준비했다.

필요한 보강:

- Gemini API 실제 호출 계층이 필요하다.
- `.docx`, `.pdf` 제출 파일 본문 파서가 필요하다.
- 멘토링 기록과 후속 조치가 학생 상세에 누적되어야 한다.
- 취업 지원 문서별 피드백 타입을 확장해야 한다.

## 우선순위

1. 위험 신호 타임라인과 추천 대응을 보강한다.
2. 피드백 메뉴에 실제 AI API 호출과 파일 파서를 연결한다.
3. 과정 보고서 출력 기능을 추가한다.
4. 유사 학생 비교와 분류 변경 이력을 추가한다.
5. 기수 간 비교와 운영 개입 효과 분석을 추가한다.
