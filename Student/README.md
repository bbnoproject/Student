처음 이어받는 사람은 먼저 [HANDOFF.md](./HANDOFF.md)를 읽어주세요. 해당 문서에 프로젝트 의도, 데이터 흐름, 학생 상태 분류 규칙, 재가공 명령, UI 판단 기준, 주의사항을 정리했습니다.

가장 최신 작업 맥락은 [HANDOFF.md](./HANDOFF.md)의 `15. 2026-05-15 최신 작업 컨텍스트` 섹션에 정리되어 있습니다. 다른 PC에서 이어서 작업할 때는 이 섹션을 먼저 확인하면 됩니다.

## 빠른 실행

1. `App/index.html`을 브라우저에서 열어 과정 개요를 확인합니다.
2. 데이터 원본을 바꾼 경우 아래 순서로 재가공합니다.

```powershell
$env:PYTHONIOENCODING='utf-8'
& "C:\Users\KGA_JJ\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" .\scripts\build_app_data.py
& "C:\Users\KGA_JJ\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" .\scripts\reprocess_student_data.py
```

다른 PC에서 위 Python 경로가 없으면 로컬에 설치된 Python으로 실행합니다.

```powershell
$env:PYTHONIOENCODING='utf-8'
python .\scripts\build_app_data.py
python .\scripts\reprocess_student_data.py
```

### 검증 자료 기반 개별 강점

`strengthProfile` 데이터 구조를 추가했습니다. 모든 학생에게 아래 구조가 생성됩니다.

- `overview`: 취업 지도용 한줄 강점, 신뢰도, 요약
- `motivation`: 게임업계 진입 동기 유형, 이유, 근거, 부족한 부분, 코칭 질문
- `strengths`: 검증 가능한 강점 카드
- `improvements`: 개선점과 코칭 질문
- `behaviorTraits`: 생활 태도와 주변 평가 기반 특징
- `employabilityAngles`: 포트폴리오/면접에서 활용할 수 있는 관점

강점 카드에는 반드시 아래 근거가 붙습니다.

- 근거 유형: 기본정보, 지원서, 실습 제출, 아침 발표, 학생간 평가, 출결 기록, 면담 등
- 근거 라벨
- 원문 발췌
- 실습 제출물의 경우 파일명과 원본 경로
- 취업 활용 방식
- 과대 해석을 막기 위한 주의 문장

개인정보 기반 강점은 엄격하게 다룹니다. 성별과 나이 자체는 강점으로 쓰지 않고, 전공/경력/산출물/거주지에 기반한 검증 가능한 설명만 사용합니다. 희망 취업 분야에 `게임`이 적혀 있다는 이유만으로 기본 배경 강점이 생성되지 않도록 조정했습니다.

### 게임업계 진입 동기 분석

지원 동기부터 이후 행동까지 함께 분석합니다.

- 지원서의 참여 신청 이유
- 희망 취업 분야

- 대원카드 원문

동기 유형은 현재 `명확`, `성장형`, `전환형`, `약함`으로 분류합니다. 동기가 약하거나 전환 서사가 정리되지 않은 경우에는 개선점에 자동으로 코칭 질문이 붙습니다.

### 실습 제출 기반 강점

실습 제출물에서 키워드와 원문 발췌를 바탕으로 강점 영역을 만듭니다. 현재 대표 영역은 다음처럼 취업 지도에 바로 활용할 수 있게 구성했습니다.

- 세계관/서사/연출
- 시스템/규칙/밸런스
- 시장/BM/유저 분석
- UX/접근성/튜토리얼
- 데이터/지표/검증
- 협업/커뮤니케이션

단, 키워드 출현만으로 역량을 확정하지 않도록 각 카드에 `주의` 문장을 함께 표시합니다.

### 생활 태도와 학생간 평가 기반 특징

- 학생간 평가에서 긍정 언급이 있으면 협업 신호로 정리합니다.
- 아침 발표 중 지각 보완이 아닌 자원 발표는 관심사 공유와 발표 행동 근거로 반영합니다.
- 학생간 불만 언급이나 출결 이슈가 크면 개선점으로 표시하고 코칭 질문을 생성합니다.

### 최근에 Codex가 사용자에게 했던 안내

사용자에게 최근에는 아래처럼 보고했습니다.

> 새로 갱신된 작업 컨텍스트를 README에 반영했습니다. `README.md`에는 `2026-05-21 작업 기록`을 추가해서 Chart.js 적용, 개요/운영 포커스/학생관리/학생 상세/학습 과정/마일스톤 분석 목적 변경사항과 검증 기록을 정리했습니다. `App/README.md`에는 실제 화면 기준 컨텍스트를 추가했고, 로컬 서버 실행 권장, Chart.js 로컬 번들, 개요/학생관리/학생상세/학습과정 화면의 최신 동작도 함께 적었습니다. `git diff --check` 확인 결과 내용 오류는 없었고, LF/CRLF 경고와 사용자 global git ignore 접근 권한 경고만 있었습니다.

### 새 세션에서 사용자에게 먼저 되짚어 줄 말

새로 이어받는 Codex는 작업을 시작할 때 아래처럼 말하면 자연스럽습니다.

```text
README와 App/README를 읽고 최근 맥락을 파악했습니다. 최근 작업은 Chart.js를 붙여 개요와 학습과정 차트를 개선하고, 우수자/위험군 분류와 인원 수, 지역/학력 재분류, 클릭 시 학생관리 필터 이동, 학생 상세 평가 근거, 마일스톤별 Analysis Purpose를 추가한 상태입니다. 마지막으로 README에 이 이어받기 컨텍스트를 보강했고, 검증에서는 git diff --check 기준 내용 오류는 없었습니다. 이어서 어떤 화면이나 기준부터 더 다듬을지 바로 보겠습니다.
```

### 이어서 작업할 때 주의할 점

- `우수자/위험군` 판단 기준은 반드시 `App/scripts/common.js`의 공통 함수 기준으로 유지합니다.
- 개요, 학생관리, 학생 상세가 서로 다른 기준으로 학생을 보여주면 안 됩니다.
- 긴급 이슈는 단발 일정이나 가벼운 병원 방문까지 포함하지 말고, 반복되거나 복합적인 위험 신호를 우선합니다.
- 화면 검증은 사용자가 켜 둔 로컬 서버 `http://127.0.0.1:8765/index.html#overview`를 기준으로 진행합니다.
- 정적 파일 직접 열기보다 로컬 서버 확인을 우선합니다.
- 문서만 수정한 경우에도 `git diff --check`로 끝 검사를 합니다.
