# Student Dashboard Handoff

이 저장소는 학생 데이터 원본을 재가공해 로컬 웹 대시보드로 확인하는 작업 공간입니다.

처음 이어받는 사람은 먼저 [HANDOFF.md](./HANDOFF.md)를 읽어주세요. 해당 문서에 프로젝트 의도, 데이터 흐름, 학생 상태 분류 규칙, 재가공 명령, UI 판단 기준, 주의사항을 정리했습니다.

가장 최신 작업 맥락은 이 README의 `다른 PC에서 대화 이어받기`와 [App/README.md](./App/README.md)의 최신 컨텍스트 섹션에 정리되어 있습니다. [HANDOFF.md](./HANDOFF.md)는 프로젝트 전체 의도와 오래된 기준을 함께 보는 보조 문서로 사용합니다.

## 빠른 실행

1. `App/index.html`을 브라우저에서 열어 과정 개요를 확인합니다.
2. 데이터 원본을 바꾼 경우 아래 순서로 재가공합니다.

```powershell
$env:PYTHONIOENCODING='utf-8'
& "C:\Users\KGA_JJ\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" .\scripts\build_app_data.py
& "C:\Users\KGA_JJ\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" .\scripts\reprocess_student_data.py
```

다른 PC에서 위 Python 경로가 없으면 로컬에 설치된 Python으로 실행합니다.

```powershell
$env:PYTHONIOENCODING='utf-8'
python .\scripts\build_app_data.py
python .\scripts\reprocess_student_data.py
```

## 주요 경로

- `Data/`: 원본 데이터

- `App/data.js`: 앱이 읽는 통합 데이터

### 학생 운영군 판단 추가

- `App/index.html#students`에 `학생 운영군 판단` 섹션을 추가했습니다.
- 학생 운영군 판단은 좌측 `학생 운영군` 메뉴와 우측 상세 데이터 패널 구조로 변경했습니다.
- 좌측 메뉴를 누르면 우측에 해당 운영군의 인원, 비율, 공통 소재, 상태 분포, 대표 근거, 운영 액션이 표시됩니다.
- 우측 `학생 보기` 버튼을 누르면 아래 학생관리 표가 해당 운영군으로 필터링됩니다.
- 학생군은 아래 5개 기준으로 집계합니다.
  - `운영 관찰군`
  - `포트폴리오 소재 보유군`
  - `자발적 공유군`
  - `취업 메시지 구체화군`
  - `일반 관찰군`
- 우측 상세 패널에는 인원 수, 전체 대비 비율, 평균 제출 수, 평균 진로 점수, 주의/관찰 인원 수를 표시합니다.
- 우측 상세 패널에는 공통 소재, 상태 분포, 대표 학생 근거, 추천 운영 액션을 표시합니다.
- 학생관리 상단 필터 칩에 현재 `학생군` 필터가 표시됩니다.
- 학생군 필터 상태에서 학생명을 누르면 `student.html?id=학생ID&group=학생군키&tab=status` 형태로 이동합니다.
- 학생 상세의 `학생군 분류 신호` 패널은 `group` 쿼리로 들어온 학생군을 강조합니다.
- `이번 기수 기본 통계` 제목은 `기수 통계`로 변경했습니다.
- `기수 통계`의 나이대, 성별, 학력, 지역 차트는 각 분류를 누르면 학생관리의 해당 데이터 필터로 이동합니다.
- 지역은 기존처럼 `지역` 필터를 사용하고, 나이대/성별/학력은 학생관리의 `기수통계` 필터 칩으로 표시합니다.

- `평가`: 검증 자료 기반 개별 강점, 취업 지도 요약, 학생군 분류, 운영 평가 근거
- `기록`: 면담 기록 전체, 아침 발표 이력, 마일스톤별 이벤트 상세
- `추가자료`: 모집 정보, 실습 제출, 발표, 학생 작성 원문과 해석, 운영진 학생 정보 전체
- `기본정보`: 개인정보와 기본 프로필

기존 URL 탭 호환을 위해 `dashboard -> status`, `detail -> records` 별칭을 유지합니다.

### 원문과 해석 보강

- 학생 상세에는 `학생 작성 원문과 해석` 패널이 추가되었습니다.

### 검증 자료 기반 개별 강점

`strengthProfile` 데이터 구조를 추가했습니다. 모든 학생에게 아래 구조가 생성됩니다.

- `overview`: 취업 지도용 한줄 강점, 신뢰도, 요약
- `motivation`: 게임업계 진입 동기 유형, 이유, 근거, 부족한 부분, 코칭 질문
- `strengths`: 검증 가능한 강점 카드
- `improvements`: 개선점과 코칭 질문
- `behaviorTraits`: 생활 태도와 주변 평가 기반 특징
- `employabilityAngles`: 포트폴리오/면접에서 활용할 수 있는 관점

강점 카드에는 반드시 아래 근거가 붙습니다.

- 근거 유형: 기본정보, 지원서, 실습 제출, 아침 발표, 학생간 평가, 출결 기록, 면담 등
- 근거 라벨
- 원문 발췌
- 실습 제출물의 경우 파일명과 원본 경로
- 취업 활용 방식
- 과대 해석을 막기 위한 주의 문장

개인정보 기반 강점은 엄격하게 다룹니다. 성별과 나이 자체는 강점으로 쓰지 않고, 전공/경력/산출물/거주지에 기반한 검증 가능한 설명만 사용합니다. 희망 취업 분야에 `게임`이 적혀 있다는 이유만으로 기본 배경 강점이 생성되지 않도록 조정했습니다.

- 실습 제출물 수
- 취업 문서 진행 이력

동기 유형은 현재 `명확`, `성장형`, `전환형`, `약함`으로 분류합니다. 동기가 약하거나 전환 서사가 정리되지 않은 경우에는 개선점에 자동으로 코칭 질문이 붙습니다.

실습 제출물에서 키워드와 원문 발췌를 바탕으로 강점 영역을 만듭니다. 현재 대표 영역은 다음처럼 취업 지도에 바로 활용할 수 있게 구성했습니다.

- 데이터/지표/검증
- 협업/커뮤니케이션

단, 키워드 출현만으로 역량을 확정하지 않도록 각 카드에 `주의` 문장을 함께 표시합니다.

### 생활 태도와 학생간 평가 기반 특징

- 학생간 불만 언급이나 출결 이슈가 크면 개선점으로 표시하고 코칭 질문을 생성합니다.

### 개요 화면 변경

- 상단 개요는 `전체`, `일반`, `과정이탈` 중심으로 단순화했습니다.

### 이어서 작업할 때 주의할 점

- `우수자/위험군` 판단 기준은 반드시 `App/scripts/common.js`의 공통 함수 기준으로 유지합니다.
- 개요, 학생관리, 학생 상세가 서로 다른 기준으로 학생을 보여주면 안 됩니다.
- 학생관리 표의 `총점`, `초기역량`, `성장가능성`, `과정참여도`, `협업`, `진로역량`, `지원검토` 점수는 100점 만점 기준으로 산정하고 표시합니다. 산식 결과가 100점을 초과하면 100점으로 상한 처리하며, 표에서는 작은 점수 막대로 표시합니다.
- `성장가능성`은 현재 수준, 상승폭, 높은 수준 유지 여부, 최신 근거 신뢰도를 함께 반영합니다.
- `협업`은 운영진 관계·소통 메모, 같은 프로젝트 팀원 언급, PM/팀장 수행 회고, 동료 긍정·부정 발화를 분리해 가중합니다. 일반적인 선호/비선호 언급은 낮은 가중치로 참고하고, 같은 프로젝트 체크인·회고·상담 근거는 더 강하게 봅니다.
- `진로`는 높을수록 긍정 점수입니다. 단, 추상적인 희망 표현은 감점하고, 구체 직무명/지원 맥락, 자기소개서·이력서·포트폴리오·피드백 같은 객관 자료, 현장 메모의 명확한 판단, 발표 주제의 게임기획 관련성을 중심으로 반영합니다.
- `지원검토`는 좋은 점수가 아니라 운영 개입 우선도입니다. 총점과 분리되며, 점수가 높을수록 출결, 제출, 상태, 현장 메모상 우려 신호를 먼저 확인해야 합니다.
- 긴급 이슈는 단발 일정이나 가벼운 병원 방문까지 포함하지 말고, 반복되거나 복합적인 위험 신호를 우선합니다.
- 화면 검증은 사용자가 켜 둔 로컬 서버 `http://127.0.0.1:8765/index.html#overview`를 기준으로 진행합니다.
