# Student Dashboard Handoff

이 저장소는 학생 데이터 원본을 재가공해 로컬 웹 대시보드로 확인하는 작업 공간입니다.

처음 이어받는 사람은 먼저 [HANDOFF.md](./HANDOFF.md)를 읽어주세요. 해당 문서에 프로젝트 의도, 데이터 흐름, 학생 상태 분류 규칙, 재가공 명령, UI 판단 기준, 주의사항을 정리했습니다.

가장 최신 작업 맥락은 [HANDOFF.md](./HANDOFF.md)의 `15. 2026-05-15 최신 작업 컨텍스트` 섹션에 정리되어 있습니다. 다른 PC에서 이어서 작업할 때는 이 섹션을 먼저 확인하면 됩니다.

## 빠른 실행

1. `App/index.html`을 브라우저에서 열어 과정 개요를 확인합니다.
2. 데이터 원본을 바꾼 경우 아래 순서로 재가공합니다.

```powershell
$env:PYTHONIOENCODING='utf-8'
& "C:\Users\KGA_JJ\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" .\scripts\build_app_data.py
& "C:\Users\KGA_JJ\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" .\scripts\reprocess_student_data.py
```

다른 PC에서 위 Python 경로가 없으면 로컬에 설치된 Python으로 실행합니다.

```powershell
$env:PYTHONIOENCODING='utf-8'
python .\scripts\build_app_data.py
python .\scripts\reprocess_student_data.py
```

## 주요 경로

- `Data/`: 원본 데이터

- `App/data.js`: 앱이 읽는 통합 데이터
- `ProcessedData/`: 학생별 재가공 산출물
- `HANDOFF.md`: 이어받기용 작업 의도 컨텍스트

## 2026-05-21 작업 기록

이번 작업에서는 대시보드의 운영 판단 흐름을 강화했습니다. 핵심은 `개요 -> 학생관리 -> 학생 상세`와 `학습과정 -> 마일스톤 상세`가 같은 분석 목적과 근거를 공유하도록 연결한 것입니다.

### Chart.js 로컬 자산

- `App/vendor/chart.umd.min.js`를 추가했습니다.
- `App/index.html`은 CDN 대신 로컬 Chart.js를 먼저 읽습니다.
- 네트워크가 막혀도 개요/학습과정 차트가 표시되도록 하기 위한 변경입니다.

### 개요 화면 변경

- 상단 개요는 `전체`, `일반`, `과정이탈` 중심으로 단순화했습니다.
- 과정 진행률은 날짜와 퍼센트만 보여주고, 주차/세션 진행 표시는 제거했습니다.
- `운영 목적별 활용 지도`, `전체 학생 분포` 섹션은 현재 단계에서 활용도가 낮아 제거했습니다.
- `지금 볼 운영 포커스`를 현재 단계/진행 교과/우수자/위험군/최근 긴급 이슈 중심으로 재구성했습니다.
- 우수자는 `발전도`, `성실도`, `집중도`로 분류합니다.
- 위험군은 `건강`, `불성실`, `인성`으로 분류합니다.
- 우수자/위험군 차트와 행을 누르면 해당 학생만 필터링된 `학생관리` 화면으로 이동합니다.
- 최근 1개월 긴급 이슈는 단발 병원/개인 일정이 아니라 반복 건강 결석·조퇴, 늦잠 반복, 위험 출결, 낮은 제출률과 체크인 지연이 겹친 경우만 표시하도록 기준을 강화했습니다.

### 기본 통계와 분포

- `이번 기수 기본 통계`는 Chart.js 차트 기반으로 재구성했습니다.
- 학력 분류는 `대학원`, `대학졸업`, `대학재학`, `고등학교`로 정리했습니다.
- 지역 분류는 `수도권`, `강원도`, `충청도`, `전라도`, `경상도`, `제주도`로 정리했습니다.
- 지역 차트 툴팁은 세부 지역을 보여줍니다.
  - 수도권: 서울, 경기, 인천
  - 충청도: 충청북도, 충청남도, 대전, 세종
  - 전라도: 전라북도, 전라남도, 광주
  - 경상도: 경상북도, 경상남도, 대구, 부산, 울산
- 지역 차트 조각이나 범례를 누르면 해당 지역 학생만 필터링된 `학생관리` 화면으로 이동합니다.

### 학생관리와 학생 상세 연결

- 학생관리에는 `지역` 필터와 `운영포커스` 필터가 추가되었습니다.
- 개요에서 지역/우수자/위험군을 클릭하면 학생관리 상단 필터 칩에 현재 기준이 표시됩니다.
- 운영포커스 필터 상태에서 학생명을 누르면 `student.html?id=학생ID&focus=분류키` 형태로 이동합니다.
- 학생 상세에는 `우수자/위험군 평가 근거` 섹션이 추가되었습니다.
- 해당 섹션은 학생이 왜 `발전도`, `성실도`, `집중도`, `건강`, `불성실`, `인성`으로 평가되었는지 지표와 문장 근거를 보여줍니다.
- 평가 기준은 `App/scripts/common.js`의 공통 함수에서 관리합니다. 개요, 학생관리, 학생 상세가 같은 기준을 사용해야 합니다.

### 학습과정 화면 변경

- `App/index.html#process`의 개요 기준은 전체 학생의 `모집 단계부터 현재까지 관측된 마일스톤`입니다.
- 출결 기간은 과정 진행 시작일 `2025-12-08`부터 현재 날짜까지로 계산합니다.
- 과정 개요 그래프는 Chart.js 기반으로 교체했습니다.
- 그래프 툴팁은 평균 프로파일을 구성하는 세부 점수와 출결 정보를 보여줍니다.
  - 학습 자기조절
  - 참여 지속성
  - 협업
  - 회복탄력성
  - 성찰
  - 진로 목적성
- 하단에는 `마일스톤별 요약과 핵심 이슈` 카드가 추가되었습니다.
- 카드에는 참여 인원, 평균 프로파일, 출석률, 상담 건수, 긴급 확인 인원, 위험출결, 반복 케이스가 요약됩니다.
- 마일스톤 카드를 누르면 해당 마일스톤 상세로 이동합니다.

### 마일스톤별 분석 목적

- 각 마일스톤 상세 화면에 `Analysis Purpose` 섹션을 추가했습니다.
- 섹션은 아래 4개 카드로 구성됩니다.
  - 분석 목적
  - 수업/자료 범위
  - 분석 질문
  - 판단 주의
- `수업/자료 범위`는 해당 마일스톤의 실제 기간과 `App/data.js`의 커리큘럼 세션을 읽어 자동 표시합니다.
- 모집 단계는 초기 스펙, 개인정보, 학력/거주지/경력, 모집 서류, 면접 서술, 지병/건강 제약/경제적 어려움, 자기보고 데이터 신뢰도 주의를 포함합니다.
- 이후 단계는 초기 적응, 실습 심화, 팀 운영, 현재 운영, 후반 전환 준비 흐름으로 목적을 나눴습니다.
- 상세 마일스톤의 운영 비율 타임라인도 Chart.js로 교체했습니다.

새 PC나 새 세션에서 시작하는 Codex는 이 문서를 먼저 읽고, 아래 문맥을 사용자에게 짧게 되짚은 뒤 이어서 작업하면 됩니다.

### 최근 대화의 흐름

- 사용자는 단순한 데이터 목록이 아니라 `운영자가 바로 판단하고 이동할 수 있는 교육 운영 대시보드`를 원합니다.
- 사용자는 Chart.js를 사용한 시각 자료, 클릭 가능한 분류, 학생 상세의 판단 근거, 마일스톤별 분석 목적을 계속 요청했습니다.
- 개요 화면에서는 `전체`, `일반`, `과정이탈`만 상단에 남기고, 과정 진행률은 날짜와 퍼센트 중심으로 정리했습니다.
- `지금 볼 운영 포커스`는 현재 단계, 진행 교과, 우수자, 위험군, 최근 1개월의 진짜 긴급 이슈를 빠르게 보도록 설계했습니다.
- 우수자는 `발전도`, `성실도`, `집중도`, 위험군은 `건강`, `불성실`, `인성`으로 분리해야 하며, 각 분류에는 인원 수가 함께 보여야 합니다.
- 우수자/위험군 분류를 누르면 학생관리의 해당 분류 필터로 이동하고, 학생을 누르면 학생 상세에서 왜 그렇게 평가되었는지 근거를 확인해야 합니다.
- 학력은 `대학원`, `대학졸업`, `대학재학`, `고등학교`로만 구분합니다. `기타`가 나오면 원인을 파악해 재분류해야 합니다.
- 지역은 `수도권`, `강원도`, `충청도`, `전라도`, `경상도`, `제주도`로 구분합니다. 지역 차트는 세부 시도 툴팁을 보여주고, 클릭하면 학생관리 지역 필터로 이동해야 합니다.
- 학습과정 개요는 전체 학생의 모집 단계부터 현재까지 관측된 데이터를 기준으로 보며, 출결 기간은 과정 시작일 `2025-12-08`부터 현재 날짜까지입니다.
- 각 마일스톤에는 분석 목적이 있어야 합니다. 특히 모집 단계는 초기 스펙, 개인정보, 모집 서류, 면접 서술, 지병/건강 제약, 경제적 어려움, 자기보고 데이터의 신뢰도를 함께 판단해야 합니다.
- 최근 마지막 요청은 `README를 다른 PC에서 읽고 시작해도 최근 대화 맥락과 내가 사용자에게 했던 안내를 다시 말하며 이어갈 수 있게 보강`하는 것이었습니다.

### 최근에 Codex가 사용자에게 했던 안내

사용자에게 최근에는 아래처럼 보고했습니다.

> 새로 갱신된 작업 컨텍스트를 README에 반영했습니다. `README.md`에는 `2026-05-21 작업 기록`을 추가해서 Chart.js 적용, 개요/운영 포커스/학생관리/학생 상세/학습 과정/마일스톤 분석 목적 변경사항과 검증 기록을 정리했습니다. `App/README.md`에는 실제 화면 기준 컨텍스트를 추가했고, 로컬 서버 실행 권장, Chart.js 로컬 번들, 개요/학생관리/학생상세/학습과정 화면의 최신 동작도 함께 적었습니다. `git diff --check` 확인 결과 내용 오류는 없었고, LF/CRLF 경고와 사용자 global git ignore 접근 권한 경고만 있었습니다.

### 새 세션에서 사용자에게 먼저 되짚어 줄 말

새로 이어받는 Codex는 작업을 시작할 때 아래처럼 말하면 자연스럽습니다.

```text
README와 App/README를 읽고 최근 맥락을 파악했습니다. 최근 작업은 Chart.js를 붙여 개요와 학습과정 차트를 개선하고, 우수자/위험군 분류와 인원 수, 지역/학력 재분류, 클릭 시 학생관리 필터 이동, 학생 상세 평가 근거, 마일스톤별 Analysis Purpose를 추가한 상태입니다. 마지막으로 README에 이 이어받기 컨텍스트를 보강했고, 검증에서는 git diff --check 기준 내용 오류는 없었습니다. 이어서 어떤 화면이나 기준부터 더 다듬을지 바로 보겠습니다.
```

### 이어서 작업할 때 주의할 점

- `우수자/위험군` 판단 기준은 반드시 `App/scripts/common.js`의 공통 함수 기준으로 유지합니다.
- 개요, 학생관리, 학생 상세가 서로 다른 기준으로 학생을 보여주면 안 됩니다.
- 긴급 이슈는 단발 일정이나 가벼운 병원 방문까지 포함하지 말고, 반복되거나 복합적인 위험 신호를 우선합니다.
- 화면 검증은 사용자가 켜 둔 로컬 서버 `http://127.0.0.1:8765/index.html#overview`를 기준으로 진행합니다.
- 정적 파일 직접 열기보다 로컬 서버 확인을 우선합니다.
- 문서만 수정한 경우에도 `git diff --check`로 끝 검사를 합니다.
